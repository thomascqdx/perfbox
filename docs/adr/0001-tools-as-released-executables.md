# 工具以各自发版的可执行产物接入，不并入 perfbox

perfbox 把每个工具当作黑盒：从工具自己的 release 下载 exe 或 zip，用子进程按命令行调用。我们没有把各工具的 Python 源码迁入 perfbox，也没有把它们作为 wheel 装进同一个 Python 环境。

原因：七个工具的依赖和 Python 版本要求互不相同（pandas/numpy、scipy、perfetto、3.10/3.11/3.13），合进一个环境会产生依赖冲突；各工具迭代节奏不同，且都需要能脱离 perfbox 单独分发给同事。

## Considered Options

- **源码迁入 perfbox（单仓库）**：能去重体积、共享前端，但所有工具被绑在一个发版节奏上，旧仓库与新仓库会长期双份维护。
- **wheel + 共享 Python 运行时**：体积最小，但运行时需要 pip 和 PyPI，依赖冲突风险高，同事机器上最容易坏。
- **独立可执行产物（已采纳）**。

## Consequences

- 体积不去重：每个产物自带 Python 运行时，全部安装约 130 MB。靠按需下载缓解。
- 宿主只能通过命令行参数、stdout 和退出码与工具交互，进度粒度粗，除非工具额外输出结构化进度。
- PyInstaller 单文件 exe 每次运行都要自解压，任务有几秒冷启动。
- 宿主必须按进程树结束任务，因为单文件 exe 运行时是「引导进程 + 子进程」两层。
